### The 3 bugs — all fixed, unit-tested, and live-re-verified

| # | Symptom | Root cause | Fix |
|---|---|---|---|
| 1 | `trace("/products")` / `get_context("/products")` → "No entry or node matched" | `EntryPointResolver.Resolve` only matched an entry's exact `Title` ("GET /products") — never read the `Route` field, despite its own doc comment claiming it did. `ContextPackBuilder.ResolveFocus`/`ResolveFocusWithReach` (the UI's multi-card path) had the identical gap. | `EntryPointResolver.cs`: bare-route branch matches `HttpEndpoint` entries by normalized `Route`; ambiguous routes (several verbs, one path) prefer GET over failing. Same fix in `ContextPackBuilder` (the two near-duplicate resolve methods were consolidated into one `FindEntry` helper). |
| 2 | `read_source`/`node` → `lineNumber: undefined` for every EntryPoint | All 11 `IEntryPointBuilder`s built their `GraphNode(..., NodeKind.EntryPoint)` with `FilePath` but never `LineNumber`, even though every `Detection` carries a `required int LineNumber`. | Stamped `LineNumber` in all 11 builders (Http, Grpc ×2, Desktop, Cli, Worker, Functions, MessageConsumer, DomainEventHandler, Signalr, OrleansGrain, GraphQl). |
| 3 | `top_flows` → `target: null` for every flow | `GraphBuilder.Build` called `ComputeFlows(preGraph, entries)` **before** `EnrichEntryTargets` ran — `graph.Flows[i].Entry` froze the un-enriched entry. The returned entry inventory (what `entrypoints` reads) was enriched correctly, which is why only `top_flows` looked broken. | Reordered `GraphBuilder.Build`: target/group-path/score enrichment now runs on `preGraph` before `ComputeFlows`, so `graph.Flows` carries the same enriched `Target` the entry inventory does. Safe because `preGraph` and the final graph share identical nodes/edges — `DetectLayerViolations` only adds metadata on top. |

Full root-cause detail, code pointers, and the live before/after transcripts are in
`eval-results/2026-07-15/mcp-blind-drive-fix-verification.md` — don't re-derive them, that file has
`file:line` for each fix plus the actual MCP tool output before and after.
