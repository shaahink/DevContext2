# T5.6 — Studio recompute-on-change (audit C1: the token-export trust bug)

**Date:** 2026-07-16 · **Branch:** feat/tapestry-t5 (T5.1 = 89c2797)
**The captured lie (2026-07-15 audit C1):** compose at 4k → slider to 1k (meter red) →
Copy/Save/plain all serve bytes-identical output, header still "Budget: 4000".

## Fix — one re-pack path, one export path

- `schedulePack()` (350ms debounce, sequence-guarded last-wins) fires on EVERY pack-relevant
  change: card add / remove / reorder / retry / budget / intent. It always sends the WHOLE
  card set — which also kills a second, quieter lie: the pre-T5.6 pack held only the most
  recently added batch, so Copy after a second add exported a pack missing earlier cards.
- Intent change now reorders + re-packs via an explicit `(selectedIntentChange)` handler
  (the old constructor `effect` + `lastIntent` dance is gone); the server assembles in card
  order, so reorder re-packs too. No signal effects anywhere — every trigger is explicit and
  deterministic under test.
- **One `buildContext` path:** exports are exactly `serverPack()` or `null` — the legacy
  client-side assembly (old `# DevContext — Context Pack` header, `<!-- context card -->`
  markers, `~tok` estimate lines) is DELETED. `exportReady` gates Copy/Save (disabled while
  packing/stale/absent; Copy shows "Packing…" in flight). A failed re-pack CLEARS the pack —
  stale bytes cannot survive as an exportable.
- Plain format strips markdown SYNTAX but keeps every content line (headings unprefixed,
  `_meta_` unwrapped, fence markers dropped) — plain ≠ markdown bytes with zero data loss.
- Response cards correlate by (type, title) consuming queues in order — two cards sharing a
  type (the preset's two `tests` cards) no longer clobber each other.
- config/tests card specs go to the server now (real sections since T4.3; client stub filter
  removed). Save name: `${repo}-context-${date}.{md|txt}` from the session summary label.
- Scope picker: preset button disabled at 0 entries with a hint (was a silent no-op);
  "Add N to context" is a count-badged primary affordance when a selection exists.

## Session gotcha (recorded)

`ng serve`'s incremental watcher can WEDGE after a mid-edit compile error (template referenced
an input before the child declared it): the stale `vite-error-overlay` keeps intercepting
pointer events and blocks Playwright clicks even after the code is fixed, and the watcher may
stop rebuilding entirely. `pnpm build` succeeding while the overlay persists is the tell —
restart `ng serve`; don't trust HMR after a broken interim state.
