# T7.3 — Stage-waterfall honesty (2026-07-16/17)

**Checkpoint:** every second of the analysis wall lands in a named waterfall row; `--stats`
waterfall sums to ≥95% of wall time. (Proposal: "Shamshir: stages sum to ~25s of a 51s wall —
semantic-lite, graph assembly, flows, and insights are invisible in the report.")

## Root cause

`DiscoveryPipeline.AnalyzeAsync` only emitted observer stage events for Stage1/2/3 + sealing +
compression. Everything after Stage 3 ran between/after the observed stages, invisible:
per-service style rollup, **SemanticLitePopulator (Tier-B populate + call-edge upgrade — the
dominant post-extraction cost)**, gateway-route file walks, GraphBuilder + MapBuilder, insight
computation — and **FileFingerprinter ran inside the snapshot initializer AFTER
`OnPipelineCompleted` had already stopped the wall clock**, so its sha256-over-every-node-file
cost wasn't even inside TotalWall.

## Fix

Four new `PipelineStage` rows (additive enum — all observers have `_` default arms):
- `SemanticLite` — per-service style rollup + Tier-B populate + call-edge upgrade
- `GraphAssembly` — scope + gateway routes + GraphBuilder + MapBuilder + flow diagnostics
- `Insights` — post-graph insight sources
- `Snapshot` — file fingerprints + git HEAD, computed as an observed stage BEFORE the clock stops

`StreamingProgressObserver` gained labels/percent bands for the new stages (server progress UX).
