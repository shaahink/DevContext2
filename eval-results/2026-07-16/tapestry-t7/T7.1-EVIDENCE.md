## Engine fixes the new poles forced (same checkpoint, defect → fix → pin)

1. **Dot-directory solution decoy** — `SolutionDiscoveryExtractor` scanned all dirs and picked by
   depth; aspire-samples' `.github/for.dependabot.only.sln` (depth 1) beat 13 real per-sample `.slnx`
   (depth 2), titling the repo `LIBRARY for.dependabot.only (0 public types)`. Fix: solutions under
   dot-directories are never candidates (segments below root only). Same guard added to
   `ProjectRootResolver`'s walk-down. Pinned by `ExtractAsync_IgnoresSolutionsUnderDotDirectories`.
2. **Shallow scaffolding beats deep product** — the picker's shallowest-depth-group hard cut let
   `tests/SamplesTests.slnx` win unchallenged. Fix: score ALL candidates — depth −10/level,
   test/benchmark/build scaffolding −200, samples/docs −100, repo-name match +5 (W6 kept). All 6
   pre-existing picker pins stay green + `ExtractAsync_DeeperProductBeatsShallowerTestScaffolding`.
3. **FINDING (pinned pending, not fixed here)** — with the picker honest, aspire-samples' JSON style
   verdict is now `SampleCollection` (eval expectation GREEN), but the MARKDOWN render still hides it:
   every entry's provenance is under `samples/` → NoiseFilter suppresses all of them → 0 entries →
   archetype ladder lands Library ("0 public types") → the Library render has no STYLE line. A repo
   whose style says "the samples ARE the product" must render them as first-class content. That is a
   detect≠render checkpoint of its own → `[TruthPending("T8")]` on
   `AspireSamples_style_is_sample_collection_not_microservices`.
4. **GrpcServiceDetection counting clarified** — detection is one per service impl CLASS (methods
   inside), and the JSON `detections` array truncates; the per-RPC truth lives at the entry level
   (`gRPC (6)` header). Expectation written accordingly (det count 1–3 + output `gRPC (6)`).
