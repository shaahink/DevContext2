# T4.3 — `config` + `tests` sections for real (R9)

**Date:** 2026-07-16 · **Branch:** feat/tapestry-t4

## What changed

The Studio's config/tests cards were dead client stubs (`CardTypeSections` mapped both to `[]`
— "not traced, handled separately" — and nothing ever handled them; the UI spun and vanished).
Both are real server sections now, in single-focus packs (all intents) and Studio cards:

1. **config** — `BuildConfigSection`: the config keys the traced spine's own files actually read.
   `ConfigScanner.Scan` gained an `onlyFiles` subset parameter (the spine is a handful of files,
   so this is cheap at pack time — the T3.4 session-wide cache stays a server concern). Rows:
   `` `Orders:MaxRetries` (Indexer) — OrderService.cs:6 (+N more sites)``.
2. **tests** — `BuildTestsSection`: test methods whose call closure reaches a spine member
   (`GraphQuery.FindCallers` + the tests_for heuristic). Capped (10 probed members / 12 rows,
   named cap note), opens with `_best-effort: name/path/project heuristic — no rows ≠ untested_`.
3. **One heuristic source** — `IsLikelyTestMethod` moved from the gRPC service into
   `Core/Graph/TestHeuristics`; the server's tests_for RPC now calls it too.

## Bug found by the gate (pre-existing, now fixed)

The CompositionApp assembly test flagged a **794-token tests card on a fixture with no tests**:
`IsLikelyTestMethod` matched `/tests/` against the ABSOLUTE file path, and the fixture lives
under `tests/fixtures/` — so every member looked like a test. Same class as T1.5's root-relative
suppression lesson, and it was latent in the `tests_for` MCP tool for any repo living under a
tests/ directory. The path signal now matches ROOT-RELATIVE segments (`rootPath` parameter,
passed by both the pack builder and the server RPC).
