# T4.5 — Staleness verification API (R6 engine half) + MCP verify_context

**Date:** 2026-07-16 · **Branch:** feat/tapestry-t4

## What changed

v1 exactly as scoped: hash + line-count deltas per file, no diff engine.

1. **Analyze-time fingerprints** — `AnalysisSnapshot.FileFingerprints` (absolute path →
   `FileFingerprint(Sha256, LineCount)`), captured by the pipeline over every node-bearing file
   (`FileFingerprinter`, byte-level sha256 + newline count; a file unreadable at snapshot time
   simply gets no fingerprint).
2. **`ContextPackVerifier`** (Core) — per pack section, the file set = its T4.4
   `SourceLocations` (strip `:line`, re-root against `RootPath`); each file compared against
   disk NOW: `modified` (hash changed, line delta = now − analyzed), `deleted`, or `unknown`
   (no fingerprint — honesty, does NOT flip stale). Disk read once per distinct file.
3. **Proto + server** — `VerifyContext` RPC (focus + optional budget; rebuilds the focus's
   sections — cheap, the graph is immutable since analyze) returning per-section verdicts plus
   `analyzed_git_head` / `current_git_head` as a whole-repo drift signal. Also shipped the T4.4
   provenance fields on `ContextSection`/`SectionAllocation` in the same regen
   (`pnpm gen:proto` + `pnpm check` green, 27 app tests).
4. **MCP `verify_context`** (24th tool, additive) — focus/query synonym contract (T3.1),
   self-describing `method` note (T3.6), compact JSON.
