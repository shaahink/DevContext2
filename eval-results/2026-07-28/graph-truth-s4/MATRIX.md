## Instrument changes (declared BEFORE the batch, with the reason)

1. **The DI-interface test was case-INSENSITIVE.** `$DiInterfacePattern = "^I[A-Z][A-Za-z0-9_]*$"`
   is applied with PowerShell `-match`, which ignores case by default, so it matched *every* type
   whose name starts with I: `ItemPage`, `IdentifiedCommand`. eShop's 12.1% entry-target FAIL is
   mostly this. Fixed to `-cmatch`. The residue after the fix is the REAL defect and is declared as
   a must-flip cell below.
2. **The fixture deny pattern matched substrings across camel humps.** `(?i)(test|fixture|mock|
   fake|stub)` matches `Crea` + `teSt` + `ream` -- MediatR's production `Mediator.CreateStream` was
   reported as a "test/fixture hub". Replaced by camel-hump tokenisation: a title is fixture-ish
   only when one of its *words* is test/fixture/mock/fake/stub (plural forms included).
3. **hub-sanity gets a minimum-degree floor** (the S4 instrument note carried from S3): on a small
   graph a degree-1 node lands in the "top 5", so the check reported on nodes that hub nothing.
   Nodes below degree 3 no longer count as hubs; when no node clears the floor the check SKIPs.
4. **sln-scope stops being a pure disk count.** Today: >1 sln on disk = FAIL, unconditionally. That
   is the right RED for a silent pick, but the fix R2 asks for is not "analyse everything" -- it is
   "say what you analysed and let the user pick". So the check now reads the analysis's own scope
   note out of `kernel.json` and PASSes when the note is present and honest (names the analysed
   solution, counts the ones on disk, matches the harness's own count). No note, or a wrong count,
   is still FAIL. `multiSlnOk` opt-outs are removed -- nothing is grandfathered.
5. **A pole may declare `"sln"`** in its expectation, passed to the CLI as `--sln`. This is how the
   flag is measured from a repo root rather than by pointing the tool at a subdirectory.
