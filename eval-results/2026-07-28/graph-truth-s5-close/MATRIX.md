### The declared MUST-FLIP, landed after this grid

`Orleans` entry-target was still **FAIL** in the grid above, and the reason is worth keeping: the fix
worked everywhere EXCEPT the shape it was written for. `AddLambdaSeams` emits its own Calls edges, and
only the emission in `AddSeamsFromDetectors` had been given `GraphEdge.TargetMember` — so ordinary
members got their method names (OrchardCore: 7 bare interfaces → 0) while every minimal-API LAMBDA entry
did not, which is exactly Orleans' 12 Dashboard endpoints. Two copies of one join, inside the batch
whose whole subject is two copies of one join. A unit test then caught the second half: appending the
called member is only an improvement when the member MEANS something — a lambda ending in
`.ToListAsync()` would have read `CatalogContext.ToListAsync`, which is worse than `CatalogContext` and
is precisely what S4's deny-list probe answered KEEP BOTH about — so the append now runs the same noise
predicates the callee selection does.
