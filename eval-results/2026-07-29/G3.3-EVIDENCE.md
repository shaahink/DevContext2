# G3.3 — Snapshot-cache truth on AnalysisSummary + SessionInfo

**R4 §1 item 10.** `from_cache` / `analyzed_at` / `git_head`.
Branch `feat/graph-v2`. All artifacts under `eval-results/2026-07-29/`.

## The question the contract could not answer

G1.4 landed `AnalyzeResult.cached` — "did this call do work". Nothing answered the next question:
**what are these numbers about?** A snapshot rehydrate stops the stopwatch at the *load*, so
`elapsed_ms` on that path measures 200ms of gunzip, and the session it opens is seconds old however
old the analysis is. A three-day-old answer and a freshly computed one were the same object on the
wire, and every consumer that tried to date one got the wrong number.

### Before-state, measured (not read off a comment)

| Claim | Measured |
|---|---|
| `AnalysisSummary` has 13 fields, none about freshness | proto 154–168 |
| `SessionInfo.age_seconds` = `UtcNow - AnalysisSession.CreatedAt` | `DevContextGrpcService.cs:563` |
| a snapshot hit opens a **brand-new** session | `AnalysisSessionManager.cs:43-56` — `EngineRunner` returns `FromSnapshotCache:true` and the manager still constructs a new `AnalysisSession` |
| the app dated the card from that | `session.store.ts:146` — `Date.now() - Number(own.ageSeconds) * 1000` |
| …and printed `< 90s` as literally **"just now"** | `home-tiles.ts:253` |
| the snapshot file recorded no time and no head | `SnapshotEnvelope` = SchemaVersion + EngineVersion + Payload |

So: **the Home freshness tile said "just now" about every cache-served repo, whatever its age.**
Second lie on the same tile — it printed "Analyzed *age* **in** *elapsedMs*", which on a rehydrate
would have read "Analyzed 3d ago in 0.2s".

## What landed

- **proto** — `AnalysisSummary.from_cache=14 / analyzed_at=15 / git_head=16`;
  `SessionInfo.from_cache=11 / analyzed_at=12`. ISO-8601 UTC, second resolution, **empty when
  unknown** (never a confident `0001-01-01`).
- **Core** — `SnapshotEnvelope.CreatedAtUtc` persists the instant; `TryLoadCachedAsync` returns it.
  Envelope metadata, so no `SnapshotSchema.Version` bump; `TryLoadAsync` keeps its shape and the
  CLI's three load sites are untouched.
- **Server** — `EngineResult.AnalyzedAtUtc` + `.GitHead`, filled on all three runner return paths.
  The rehydrate paths report the **snapshot's** instant, not the call's.
- **`AnalysisSessionManager.ResolveCommitSha`** now asks `GitHeadReader` (the reader the cache key
  already uses) before its hand-rolled `.git`-directory walk. See "the second defect" below.
- **MCP** — `analyze` returns `fromCache`/`analyzedAt`/`gitHead` and a note that names the instant;
  `list_sessions` returns `analyzedAt`/`fromCache`/`commitSha`.
- **App** — `freshnessOf()` dates the card from `analyzed_at`; the tile says "restored from
  snapshot" instead of an elapsed time when `fromCache`. This also **removes** a `ListSessions`
  round-trip per analyze (the summary now carries everything it was fetched for).
- **docs** — `docs/product/mcp-reference.md` §Session model states the `cached` vs `fromCache`
  distinction and warns to read `fromCache` before `elapsedMs`.

`cached` and `from_cache` are **not** duplicates: `cached` = "did this CALL do work" (an
already-open session makes it true with no file involved); `from_cache` = "were these NUMBERS loaded
from disk". A session reuse is `cached:true, from_cache:false`.

## The red, watched — twice

`eval-results/2026-07-29/g33/` · probes applied to the shipped code, then reverted.

**Probe 1** — swapped `AnalyzedAtUtc: cached.AnalyzedAtUtc` for `DateTime.UtcNow` on both rehydrate
paths (what the code did implicitly before this checkpoint):

```
Failed A_rehydrate_reports_the_originals_instant_not_its_own
  Expected: 2020-01-02T03:04:05.0000000Z
  Actual:   2026-07-29T10:19:07.0259516Z
```

Six years apart — the numbers came from a snapshot stamped 2020 and the server called them current.

**Probe 2** — disabled the new `GitHeadReader` line in `ResolveCommitSha`:

```
Failed A_worktree_head_is_not_the_empty_string
  Expected: "6737dd8220828856d669cd6bb94c6c43193431f4"
  Actual:   ""
```

**Why probe 1 can fail at all:** the persisted `CreatedAtUtc` is back-dated to 2020 before the
rehydrating call. Without that the two instants are milliseconds apart and `DateTime.UtcNow` has
~15.6ms granularity on Windows — the naive code would frequently produce a *bit-identical* value and
the test would pass while measuring nothing.

## The second defect, found on the way

`ResolveCommitSha` required `.git` to be a **directory**. Measured on this machine's own second
worktree, before writing any code:

```
ls -ld C:/Code/DevContext2-ui/.git   ->  -rw-r--r--  58 bytes   (a FILE, the gitdir pointer)
C:/Code/.git, C:/.git                ->  absent
git -C C:/Code/DevContext2-ui rev-parse HEAD -> 8dbb5106c03544c4318b866b5e065b91bbc17b1c
```

The walk runs off the end of the path and returns `""`. AGENTS.md tells agents to drive this repo
**from worktrees**, so the app's HEAD-sha chip was blank in exactly the recommended setup. Same
function also missed **packed refs** (no `.git/refs/heads/<branch>` file after `git gc`), and was a
*second* notion of HEAD from the one the snapshot cache keys on. `A_worktree_head_is_not_the_empty_string`
builds a real `git init` → commit → `git worktree add` and pins it.
