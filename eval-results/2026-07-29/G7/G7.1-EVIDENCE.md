Three distinct defects, one per unexplained section:

1. **Hub radar issued an instruction the reader cannot act on.** There is nothing to index on a repo
   with zero entry points. Same defect class T6.0 S1.8 fixed for the event board and never swept for.
2. **Per-service breakdown described an empty set as a set** — *"The 0 services…"* — and printed a
   **second** empty notice underneath it from inside `app-service-cards`. Two messages, neither
   saying why a library has none.
3. **Data stores was not a "nothing found" at all.** Its only inputs are the per-service style stacks
   and the ServiceMap cards, and **both are empty by construction when a repo has no services**. The
   section examined nothing and reported *"No data-store signals detected"*, which a reader takes as
   a finding about the repo. *Nothing was looked at* and *nothing was found* are different sentences,
   and the page was saying the wrong one. This is the C-2 defect in its sharpest form.

## 3. What landed

**The rule, made structural.** `src/app/ui/withheld/withheld.ts` — one component carrying the S9
shape: keep the heading, keep the page's shape, state the reason in place of the content. It renders
`data-withheld` + `data-reason`, so a withheld section is **structurally** distinct from content. A
text grep would pass on a page that had simply deleted the section, which is the defect S9 named.

Three reason classes, and they are not interchangeable:

| reason | meaning |
|---|---|
| `archetype` | the subject does not exist for this kind of repo (a library has no services, so no per-service data stores) |
| `none-found` | the subject exists, was examined, nothing matched |
| `not-computed` | the subject exists, the data has not been produced yet (indexing) |

**The decisions, made testable.** `src/app/features/pages/atlas-sections.vm.ts` — five pure
functions over one `AtlasSectionFacts` object, so the rule is unit-tested **in the battery**
(`atlas-sections.vm.spec.ts`, 10 cases) rather than only observed through a DOM probe. One facts
object so a new section cannot invent a second source for a fact another section already states.

**Per section:**

- *Architecture* — content marked; withholds when no project resolved. Caption pluralization fixed
  ("1 dependency edge", "The 1 service").
- *Top flows* — entry-less → `archetype`; entries but no ranked flows → `not-computed` / `none-found`
  by index status.
- *Event & queue board* — T6.0's honest text kept, given its reason class; the non-library
  entry-less case no longer claims a library surface.
- *Data stores* — no services → `archetype`, naming the per-service input. With services → `none-found`,
  **stating how many were scanned**.
- *Per-service breakdown* — an empty set withholds the section instead of captioning itself; the
  duplicate notice inside `app-service-cards` is now reached only in the genuinely different state
  where services exist but no style row came back, and says so.
- *Cross-cutting* — `none-found`, naming both things it looked for.
- *Hub radar* — entry-less → `archetype` naming the ranking rule (`FlowIndexBuilder.TopHubDegrees`
  keeps nodes on **more than one** flow); the actionable instruction survives only where it is
  actionable.

25 event wires, 3 data stores, 10 hubs).

## 6. Found, not fixed

**bug #20** — AutoMapper (a packable library) reads *"1 services (1 drawn)"* and the per-service
breakdown draws a card for **TestApp**, its auxiliary demo executable. `ArchetypeDetector` already
excludes "auxiliary samples/benchmarks that reference the library" when deciding Library;
`ServiceBoundaryInference.RunnableProjects` does not apply the same exclusion. Two judgements about
the same projects, one narrower than the other. Engine work, same auxiliary-executable root cause
**G9.1** is chartered for.

**Method note.** The probe PASSED on AutoMapper before I read its dump — a structural invariant
cannot see a section that fills with the *wrong* content. Keep the full-text dump in every DOM probe:
the verdict line is not the evidence, it is the index to it.
