## What changed

| Half | File | Change |
|---|---|---|
| Catalog | `Graph/EntrySurfaces/EntrySurfaceCatalog.cs` | `quartz` + `hangfire` descriptors declare `Kind: ScheduledJob`, `RenderLabel: "Scheduled"`. `Role` stays `FrameworkLibrary` — the MassTransit precedent (a library signal that still declares a Kind), which keeps `ArchetypeDetector`'s `AppEntryKinds` unchanged so no repo's archetype moves. |
| Detection | `Extractors/Generic/ProgramCsFlowExtractor.cs` | Reads Hangfire (`RecurringJob.AddOrUpdate<T>`, `BackgroundJob.Enqueue<T>/Schedule<T>`, and the `IRecurringJobManager`/`IBackgroundJobClient` forms) and Quartz (`AddQuartz(q => q.AddJob<T>/ScheduleJob<T>)`) **registration syntax** → `BackgroundWorkerDetection` with `Kind: TimedJob`. **The first producer TimedJob has ever had.** `ExtractSchedulerJobs` generalised to take service type / kind / method names; the DNTScheduler path is unchanged. `StartupCompositionTokens` gains `AddQuartz`/`RecurringJob`/`BackgroundJob` so a factored-out `JobRegistration.cs` joins the walk-set. |
| Builder | `Graph/EntryPoints/WorkerEntryPointBuilder.cs` | A class implementing Quartz `IJob`, or carrying a Quartz (`DisallowConcurrentExecution`, `PersistJobDataAfterExecution`) or Hangfire (`RecurringJob`, `AutomaticRetry`, `DisableConcurrentExecution`) job attribute, mints a `ScheduledJob` entry — **gated on the framework's own signal**. `Execute` added to the entry-anchor member list (Quartz's `IJob` method). |
| Doc | `docs/product/TRACE-RULE-REFERENCE.md` §1.1 | The `ScheduledJob` and `HostedService` rows now name their real resolver and real sources. |

**Why registration syntax and not a body rule.** D1.2 measured that the only evidence a worker is
timer-driven lives in its body, and both carriers of a body (`TypeDiscovery.SourceBody`, `BodyFacts`)
are populated only under Full/Debug — a body rule would make an entry's *kind* depend on the
extraction profile. Registration syntax in a startup file is visible in every mode. That is why
D1.2's allow-list entry named this the honest producer, and it is what shipped.

**Why the interface/attribute path is signal-gated.** `IJob` is not a Quartz-owned name — repos
declare their own — and the attribute names are just as guessable. The gate reads the signal, which
comes from the catalog descriptor's `Packages`, so the gate *is* the descriptor's declaration rather
than a second list that can drift from it.

## Declared OUT of scope, and why

The `kind:ScheduledJob@-` line stays in `catalog-reachability-allow.txt`. Its fixture is a
`PeriodicTimer` `BackgroundService` registered with `AddHostedService<T>`, which still produces a
`HostedService` entry and **should** — that shape carries no scheduler evidence outside its body.
Closing that line would mean editing the fixture to match the fix, which is the one move this
program does not make. D1.2's prediction on that line ("set `BackgroundWorkerKind.TimedJob` there
and this line goes away") was measured and is *half* right: TimedJob now has a producer, but not for
that shape. The line's reason text was updated to say so.
