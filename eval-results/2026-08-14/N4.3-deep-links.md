## What was wrong

The live feed could name the symbol an agent had just read and gave the reader no way to follow it.
Watching was all you could do — the audit's "observation deck with the instruments facing the wrong
way", one instrument later. `ToolCallEvent` field 11 had been left `reserved` on purpose by s21:
R-T1 says a field lands with its reader, and the reader is this navigation.

## What landed

| Piece | File | What it does |
|---|---|---|
| `primary_arg = 11` | `proto/devcontext/v1/devcontext.proto:1174` | the ONE argument that says what a call was about |
| the reader | `src/DevContext.Server/Endpoints/DevContextGrpcService.cs:900` | decodes `x-mcp-arg1-b64` beside `args_digest` |
| the route table | `src/DevContext.App/src/app/features/pages/mcp-page.ts` (`ROW_ROUTES`) | keyed on the **RPC that ran**, read off the generated service descriptor |
| the affordance | same file, feed row (`data-testid="feed-open"`) | `open ↗` / `replay ↗`, absent when the row has no subject |
| the cross-repo guard | same file (`ensureRepoOpen`) | adopts the agent's live session, or refuses out loud |

**The design decision worth keeping.** The route is keyed on the gRPC method the server recorded,
never on the MCP tool name. A table of tool names kept in this page is precisely the defect
BUG-BACKLOG #4 was, and the served catalog killed it three commits ago; re-introducing one to
decide navigation would have grown it back in a new place. The gRPC method is a contract this app
already binds to, so the keys are `DevContextService.method.getTrace.name` and friends — rename an
RPC in the proto and the page stops **compiling** instead of quietly linking nowhere. A new MCP verb
that calls `GetTrace` inherits the link for free.

The rule: *open the subject in the room that answers that question*. `GetTrace`/`GetNode`/`GetImpact`
→ Explore focused on it. `GetContext`/`GetContextPack` → Studio, replayed with the same
symbol-rooted seeds (`flow`/`bodies`/`usage`) the NodeCard and Insights send, so a replay and a
hand-off produce the same pack for the same symbol.

**Cross-repo.** An agent calls whatever repo its host pointed it at, which is frequently not the one
open in the window. Resolving its symbol against this graph would answer nothing — or worse, a
same-named type in another codebase. The row's repo is opened first (adopting the live session the
server has held all along; the session table above the feed is the same list), and a row that cannot
be opened refuses with a toast instead of navigating.

## The probe is now a gate

`eval/gates.ps1` step 2c runs it after `partial-truth`, under the same TodoApi submodule guard (a
missing pin prints the hole, it never silently passes). It fails the battery on any red. Reason:
both halves of a deep link are wire data, and if either stops arriving the button is simply *not
there* — nothing errors, nothing logs. That is the failure shape this program keeps paying for.
