## The one E1-scoped defect in that list, fixed — #3

### Root cause, measured in the source

`MediatRExtractor.TryParseHandlerType` treated a **request marker** as a handler declaration. For
`CreateOrderCommand : IRequest<bool>`, `baseName` is in `RequestMarkers`, `args.Length == 1`, and it
returned `RequestType: "bool"`. `EmitHandlerJoin` then minted `Type:bool` — tagged `command`, in no
project — tagged `CreateOrderCommand` with `RoleTags.Handler`, and drew the edge. The same path turned
`IdentifiedCommand<T, R> : IRequest<R>` into the node **`Type:R`**: a generic *parameter* as a graph
node. `IRequest<TResponse>`'s type argument is the RESPONSE; the implementing class IS the request.

The non-generic branch already knew this (it returned `"<self>"`) — and still emitted an edge, so
`Type:<self>` was the same phantom waiting for a repo that uses a bare marker. The red-first fixture
proves it: the builder minted `GraphNode { Id = Type:<self>, Title = <self> }`.

### RED first — 5 of 6, log `red-before-requestmarker.txt`

```
Failed:  5, Passed:  1, Total:  6   (tests/DevContext.Core.Tests/Graph2/RequestMarkerJoinTests.cs)
  A_request_marker_names_itself_...  IRequest<bool>   FAIL  expected "<self>", actual "bool"
  A_request_marker_names_itself_...  IQuery<OrderDto> FAIL  expected "<self>", actual "OrderDto"
  A_request_marker_names_itself_...  ICommand<int>    FAIL  expected "<self>", actual "int"
  A_generic_parameter_never_becomes_the_request_type  FAIL  expected "<self>", actual "R"
  A_request_marker_detection_draws_no_edge_...        FAIL  Type:<self> was minted
  A_real_handler_interface_is_untouched               PASS  <-- the pin
```

The single PASS is the pin that stops the fix trading one spelling for another:
`IRequestHandler<CreateOrderCommand, bool>` must keep parsing as it did. After: **6/6**.

### The fix — one rule, and the surfaces that render it (R-T1)

`MediatRExtractor.SelfRequest` (`"<self>"`): a request marker reports itself as the request and its
**last** type argument as the response, at every arity. `EmitHandlerJoin` tags such a subject with its
KIND and returns — no minted node, no edge, and no `handler` tag (which is what had labelled a request
a handler). The marker's subject is also no longer seeded into `knownHandlerTypes`, where it told the
transitive walk that a request was a known handler. `MarkdownRenderer` (handler table + endpoint
linkage) and `HtmlContextRenderer` skip marker detections: the row they used to draw was
`| Command | bool | Unit | CreateOrderCommand |`.

`GraphBuilder.Nodes.cs:576` and `GraphBuilder.Seams.cs:340` also read `RequestType` and needed no
guard — measured: both gate on `Kind == Notification`, and no marker yields that kind.
