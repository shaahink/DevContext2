## The problem the capture had to solve, and how it was solved honestly

The MCP feed **has no backlog**: `ObserveToolCalls` writes to a channel per observer and replays
nothing (`DevContextGrpcService.cs:860-882`). A shot of `/mcp` on a quiet machine therefore shows
the empty state — *"No agent calls yet"* — and cannot show the affordance N4.3 built. The feed also
defaults to **agents only**, so the app's own gRPC traffic does not fill it either, and a UI-origin
row carries no `primary_arg` and therefore no link.

Faking rows was not an option on a page whose whole redesign was about not performing. So the
capture drives a **real MCP sidecar** at the same server the browser is watching:

```
devcontext-mcp.exe  --stdio-->  DEVCONTEXT_ENDPOINT=http://127.0.0.1:5179  (the dev server)
   initialize → analyze(eShop) → entrypoints → trace(focus) → get_context(focus)
```

`ServerShim.EnsureServerRunning` reuses whatever answers `/health` at that endpoint, so the calls
land on the running server, are tagged `agent` by the origin middleware, and stream to the open
page. This is the screenshot-side twin of `eval/mcp-qa/deep-link-truth.js`, which measures the same
rows on the wire. New file: `src/DevContext.App/scripts/seed-agent-calls.mjs` (the sidecar driver);
`capture-readme.mts` gained a per-shot timeout override and calls it from the two MCP shots.
