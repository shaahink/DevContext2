## Item 1 — TraceNode gains structured `file_path` + `line_number`

**Before (measured, not read off a comment):** `TraceNode` carried `provenance` only, as the string
`"C:\repo\src\X.cs:47"`. Two clients re-invented the split independently —
`view-models.ts:relativizeProvenance` and `inspector.ts:relProvenance`, both doing
`lastIndexOf(':')` and both having to get the drive-letter colon right.

**After:** `proto TraceNode.file_path = 16`, `line_number = 17`, populated in
`ProtoMapper.ToProto(TraceStep)` via a single Core helper, `PathDisplay.SplitProvenance` — placed
beside `PathDisplay.RelativeProvenance`, which already owned that rule.

**Honesty decision:** a step whose provenance is a bare path (EntryPointResolver emits these for
`PublicApi` entries) leaves BOTH fields unset rather than shipping `line_number = 0`. Half a site
is worse than none — a client would anchor a reader at the top of the file and call it the
declaration.

**Reader:** `TraceNodeVm.filePath/lineNumber` (`view-models.ts`), consumed by
`inspector.ts:relProvenance(step)`, which no longer parses the wire string.

## Item 4 — ProtoMapper stops dropping four honesty fields

**Before (measured):** `TraceStep` carries `OmittedNames`, `MultiImplCount`, `DiHostCount`,
`TestOnly`. `Rendering/TraceRenderer.cs` renders all four (`[×N impls]`, `[×N hosts]`,
`[test-only registration]`, `(N branches omitted: A, B, …)`). `ProtoMapper.ToProto(TraceStep)`
mapped **none** of them. The GUI therefore showed a multi-implementation DI resolve as if it were
the only binding, and a cut subtree as a bare count — detect≠render, on the wire.

**After:** `omitted_names = 18`, `multi_impl_count = 19`, `di_host_count = 20`, `test_only = 21`,
all mapped, recursively through children.

**Reader:** `features/trace/trace-node.ts` renders all four at CLI parity — the omitted NAMES with
the ellipsis rule (`names.length < omitted` → trailing `…`), and the three DI annotations as badges
that appear only when they have something to say (`> 1`, not `> 0`).

## Item 2 — `ReadSource` FILE mode with caps

**Measured first:** the MCP `read_source` tool does **not** call the `ReadSource` RPC — it calls
`GetNode` and reads the file itself in-process (`DevContextTools.cs`). The RPC's only client is the
app's Inspector Code tab, so that is where the FILE mode reader had to land. (Filed as a bug — see
below.)

**After:** `ReadSourceMode.READ_SOURCE_MODE_FILE = 3`; `ReadSourceRequest.file_path = 5` (optional)
and `max_lines = 6`; `ReadSourceResponse.total_lines = 7` and `truncated = 8`.

- Addressable **by path or by node** — a caller holding a `file:line` (which every provenance now
  is) can read that file without turning it back into a graph node.
- Caps: `DefaultFileLines = 2000`, `MaxFileLinesCeiling = 10000`, clamped server-side.
- **The cap is visible.** `total_lines`/`truncated` are set for MEMBER and WINDOW too — those were
  always windows; they just never said what they cut.
- **Containment.** A caller-supplied path is the one place a query API turns into "read any file on
  this box". `ResolveInRoot` refuses anything outside `Snapshot.RootPath`, with the refusal in the
  response body rather than a silent empty read.

**Reader:** Inspector Code tab — a `whole file` chip (`data-testid="load-whole-file"`) plus a range
note (`data-testid="code-range"`) driven by `rangeNote()`, which states the server's numbers and
deliberately does not interpret them (the same `truncated` flag means "FILE cap fired" in one mode
and "this is a member window" in another).

## Item 3 — per-file edge overlay on the wire

**After:** `rpc GetFileOverlay(FileOverlayRequest) returns (FileOverlayResponse)`, served from a new
`GraphQuery.EdgesInFile(path)` (Core) that walks `AllEdges`, splits each `Provenance` with the same
`PathDisplay.SplitProvenance`, and returns `FileEdgeSite` rows ordered by line.

Every other browse RPC is node-first; this one is file-first, which is the only way to read code
with its edges in the margin.

**Honesty decisions:**
- An edge provenanced to the file with **no parseable line** is returned with `line = 0`, not
  dropped: `placed_sites` / `unplaced_sites` make coverage visible instead of making the overlay
  look more complete than it is.
- `from_node_id` was drafted and then **removed from the proto** (field 4 left unused, with the
  reason in the file): no surface renders it, and a field no client reads is exactly the
  dead-by-construction defect the sweep exists to catch. Adding it back when the Reader needs it is
  one line.
- Containment is the same `ResolveInRoot` guard.

**Reader:** Inspector Code tab renders the coverage line
(`data-testid="overlay-coverage"` — "N wiring sites in this file · M placed on a line · K known but
unplaced") and one clickable row per site (line · kind · target · `approx` mark), navigating to the
target node.

`tests/DevContext.Server.Tests/ProtoMapperTraceHonestyTests.cs`
- `MapsTheFourFieldsThatUsedToBeDropped` — the exact regression this checkpoint fixes.
- `SplitsProvenanceIntoTheSiteAsData_KeepingTheTextForm` — structured site AND the text form.
- `LeavesTheSiteUnsetWhenProvenanceHasNoLine` — no invented line 0.
- `MapsChildrenRecursively` — the mapper recurses; a root-only fix would pass everything else.
- `SplitProvenanceIsTheOneParse` (Theory ×5) — drive-letter colon, POSIX path, bare path,
  non-numeric suffix, empty.

a real analyzed snapshot, `tests/fixtures/ControllerApp`)

  response cannot report a size it did not return.
- `FileMode_CapFires_AndTheResponseAdmitsIt` — `max_lines: 2` → `truncated`, `total_lines > end_line`.
- `FileMode_RefusesAPathOutsideTheAnalyzedRoot` — a real readable file outside the root is refused.
- `FileMode_AcceptsARepoRelativePath` — relative and absolute give identical content.
- `FileOverlay_ReturnsTheWiringSitesInThatFile_OrderedByLine` — sites found on a real snapshot,
  `placed + unplaced == sites.Count`, ordered.
- `FileOverlay_RefusesAPathOutsideTheAnalyzedRoot`.

`src/DevContext.App/src/app/features/trace/trace-node.spec.ts` (new; the component had no spec)
- omitted NAMES rendered, ellipsis rule, bare-count fallback, the three DI badges, and the
  "says nothing when there is nothing to say" case (`multiImplCount: 1` renders no badge).

`src/DevContext.App/src/app/features/inspector/inspector.spec.ts` (new)

`src/DevContext.App/src/app/models/view-models.spec.ts` (extended)
