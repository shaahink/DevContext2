# T1.2 — the menu is curated: 14 advertised, 8 unlisted, nothing deleted

**Checkpoint:** T1.2 (stage T1, W1 agent-surface trust pack) · **Date:** 2026-08-13 ·
**Branch:** `feat/pre-release-engine`
**Instrument:** `eval/mcp-qa/wire-truth.js` (extended this checkpoint) — a real MCP handshake, a real
`tools/list`, a real call to an unlisted tool, and a real call to a name that does not exist.

## 1. The decision

DEEP-EVAL §4 W1.2 named the candidate core surface — "roughly PRODUCT-DIRECTION §7's set plus the
navigation primitives" — and said to demote or fold the rest. What shipped:

**Advertised (14):** `analyze` · `overview` · `map` · `stats` · `entrypoints` · `resolve` · `find` ·
`neighbors` · `usages` · `trace` · `impact` · `seam` · `read_source` · `get_context`
— §7's MCP list (`entrypoints`, `trace`, `map`, `stats`, `node`→`resolve`, `usages`) plus the
navigation primitives and the two pack tools DEEP-EVAL's candidate names.

**Unlisted specialists (8), each with the line an agent gets when it calls one:**

| Tool | Why it is off the menu |
|---|---|
| `status` | session lifecycle — `analyze()` is idempotent and hands back the handle |
| `list_sessions` | session lifecycle — an ambiguous handle-less call already names the open sessions |
| `close_session` | session lifecycle — sessions expire; this is server housekeeping |
| `top_flows` | `entrypoints()` already returns the top-N by the same score |
| `node` | `resolve()` already returns title/kind/service/path; `neighbors()` carries the degrees |
| `config` | ask it when the question is specifically about configuration keys |
| `tests_for` | ask it when the question is specifically about test coverage of a symbol |
| `verify_context` | ask it when a pack has been open long enough that the files may have changed |

**Demoted, deliberately, rather than retired.** `config`, `tests_for` and `verify_context` answer
questions no other tool answers, so retiring them would have been a capability cut wearing the word
"curation"; and `list_sessions`/`close_session` are the session plumbing three QA harnesses drive.
So a specialist is **built from the same method with the same described schema** and
`UnknownToolHandler` dispatches a call by name straight to it (`McpServerTool.InvokeAsync`). The
price of a specialist is that you have to know its name — the right price for a tool nine sessions
in ten do not want — and the unknown-tool envelope names all eight so they stay discoverable.

The split is carried by `[SpecialistTool("why")]` **on the method**, and `McpToolMenu` is the only
thing that reads it. That is the G2.1 lesson applied again: the hand-maintained array of tool names
was correct the day it was written and had no way to stay correct.

## 3. What it costs, end to end

Three measurements of the same statistic (`measure-tax.mjs`, unchanged arms and prompt), one per
state of the menu:

| menu state | tools on the wire | `tools/list` chars | schema tax (turn-1 prefix, B−G) | cold write |
|---|---|---|---|---|
| P1.2 baseline — 22, all undescribed | 22 | 6055 | **2540** | $0.0254 |
| after T1.1 — 22, all described | 22 | 16730 | **6549** | $0.0655 |
| after T1.2 — **14 described** | 14 | 12347 | **4863** | $0.0486 |

Curation gave back **1686 tokens (−26%)** of what describing the tools cost. Net against the
pre-W1 product: **+2323 tokens (+91%)**, buying 14 tools that say what they are and 52 parameters
that say what they take, where there were 22 names and nothing else.

That is the trade DEEP-EVAL W1.2 asked for, and it is not self-justifying: A1.2's `mcp_call_share`
against the 0.2 floor is the number that says whether it was worth 2.3k tokens. Both readings are on
disk (`eval/agent-probe/results/p1.2-tool-schema-tax{,-post-t1.1,-post-t1.2-curated}.md`) so that
question can be asked against real figures rather than an estimate.
