## What changed

**Engine — `src/DevContext.Core/Graph/ContextPackBuilder.cs`**

- Multi-entry section merge now unions `SourceLocations` (deduped, ordinal-sorted, capped at 20 — the same
  cap the single-entry path uses at `:824`) and sums `Verified`/`Approx`.
- `AllocatedTokens` is now the sum of the per-entry budgets that reached an entry which actually produced
  sections (`≤ totalBudget`), instead of `totalBudget` verbatim. Three different numbers now: pack cost,
  allocation, ceiling.

**App — `context-studio.ts`, `composition-view.ts`, `budget-panel.ts`**

- All four Studio copy paths (preview Copy, per-card copy, provenance-chip copy) go through
  `core/clipboard.ts::copyToClipboard`, which is the Tauri-aware one — `navigator.clipboard` is the API
  that is unreliable in WebView2, i.e. exactly in the shipped desktop shell.
- Copy toast + the "Copied!" label are set after the write resolves; a rejection now toasts
  `Copy failed: <message>` instead of vanishing. `BudgetPanel.copied` became an `input` owned by the
  parent that performs the copy (the child can no longer claim an outcome it does not observe).
- Save toasts after the export call completes and says `Downloading <file>` — this path hands the file to
  the webview download, so it no longer claims a save location it never chose. (N3.2 replaces this path
  with a real `.devcontext/packs/<slug>.md` write; the wording is honest about today's mechanism.)
- Preview header gained a title explaining that total / allocated / budget are three different numbers.
