## #6 — trace by nodeId

Pre-fix, TodoApi (`pre-fix/trace-by-nodeid.json`): **10 of 12** nodeIds answered `found:false`
while the same node's bare title traced steps, e.g.

```
EntryPoint:GET /                          id=(miss)  bare=5 steps
Type:Todo.Web.Server.ExternalProviders    id=(miss)  bare=2 steps
```

Post-fix, same 12 ids, same session shape:

```
EntryPoint:GET /          found:true  steps:5   bare:5   "Entry: EntryPoint: GET /"
EntryPoint:POST /todos/   found:true  steps:3   bare:3
EntryPoint:GET /todos/    found:true  steps:2   bare:2
```

The vacuous shape now explains itself instead of returning an empty tree:

```
Type:TodoApi.ExternalUserInfo -> found:true, steps:0, note:
  "0 steps: nothing outbound was resolved from 'ExternalUserInfo' - it calls, sends or handles
   nothing the graph could bind. Its callers are the other direction:
   neighbors(nodeId:"Type:TodoApi.ExternalUserInfo", direction:"in"), or usages(...)."
```

**Root cause, measured not assumed.** `EntryPointResolver` never recognised the `Kind:Key` form the
rest of the tool menu speaks. The string fell through to `ResolveFromNode`, which splits at the FIRST
colon and read the **kind prefix as a type name**. On TodoApi nothing is titled `EntryPoint`/`Type`, so
it missed; on Hangfire (2026-07-29) a node titled literally `Type` existed (bug #7's mis-bound node)
and it matched THAT — `found:true`, 0 steps, `"Entry: Type: Type"`. One tier kills both shapes, and it
returns the **inventory entry** when the node is one, so an endpoint keeps its route, verb and provenance.

The phantom half cannot be reproduced on TodoApi, so it is pinned by a unit test on a synthetic graph
carrying a node titled `Type`: `EntryPointResolverTests.Resolve_of_a_nodeId_never_lands_on_a_node_titled_like_its_kind`.

## #2 — entrypoint names round-trip: RE-MEASURED, DOES NOT REPRODUCE

Measured 2026-07-29 on TodoApi: `entrypoints` showed `GET /todos` and `get_context` answered
"No context could be built", offering `Member:TodoApi.TodoApi::<lambda> GET /todos/`.

```
UiEntry       "GET /"                 EntryPoint:GET /                 ctx=ok trace=5 steps
HttpEndpoint  "POST /todos/"          EntryPoint:POST /todos/          ctx=ok trace=3 steps
HttpEndpoint  "GET /todos/{id}"       EntryPoint:GET /todos/{id}       ctx=ok trace=2 steps
```

**12/12 on TodoApi, 40/40 on eShop** round-trip into BOTH `get_context` and `trace`
(`*/entry-roundtrip.json`). The minimal-API lambda titles are gone — entries are `EntryPoint` nodes
keyed by their display name, which the entry-node work after 07-29 delivered. #2 is therefore closed by
re-measurement rather than by a new fix, and the round-trip is now a standing check so it cannot
silently regress.
