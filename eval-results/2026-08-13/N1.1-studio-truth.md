## (b) Wire item 4 — the decision, and why

The audit offered two mechanisms: **`VerifyContextRequest` gains cards/intent**, or **verification
moves into `GetContextPack`'s response**. Chosen: **the second.**

The reason is not preference, it is that one of them cannot be got wrong:

- `ContextPackVerifier.Verify()` is already a pure function of `ImmutableArray<SectionAllocation>`
  (`ContextPackVerifier.cs:28`). It needs nothing but the sections.
- `BuildMulti` already **holds** the exact sections the pack kept, at the point it has finished
  keeping them — after `AllocateProportionalBudgets` (`ContextPackBuilder.cs:533/546`), after the
  card's `wanted` section filter (`:567/:581`), after the multi-entry merge (`:588-601`).
- So verifying *those* removes the divergence by construction rather than by correction. There is
  no second computation of the fact left to drift.

The three divergences BUG-BACKLOG #28 measured, and what each is now:

| Divergence (measured 2026-08-13, N0.3) | Before | After |
|---|---|---|
| **Budget** — `verifyPack` handed EVERY focus the whole ceiling (`context-studio.ts:205-217`) while the build gave each a proportional slice | 2 focuses × 4000 verified against a pack built at ~2000 each | the ledger is computed from the built sections; there is no second budget |
| **Sections** — the ledger verified everything a focus produced; the pack keeps only what the CARD asked for | a section the pack dropped could be reported "fresh"; drift in a section the pack never carried counted against it | ledger keys ≡ the pack's own section keys (asserted) |
| **Cost** — `Promise.all` over the focus list, on a path that reruns on every card edit (`:387`) | 1 + N RPCs per repack | 1 RPC per repack (asserted: `verifyContext` is never called) |

`VerifyContext` the RPC is untouched and still single-focus: MCP's `verify_context` tool reads
every field of its response (`DevContextTools.cs:1673-1715`), so nothing on that wire went dead —
`contract-sweep` confirms (below). The app's now-unused `DevContextApi.verifyContext` wrapper was
deleted rather than left as a client with no caller.

Also closed here: **`checkedAt` was dead** — set at `context-studio.ts:243`, declared at
`verification-panel.ts:10`, rendered nowhere. The panel now prints when the ledger was taken
(`data-testid="verification-checked-at"`). A freshness verdict that cannot say when it looked is
not evidence.

**Cost note (stated, not hidden):** the pack path now calls `GitHeadReader.Read` once per build
(one `git rev-parse` spawn) to report HEAD drift. The path it replaced spawned one *per focus* per
repack, inside the grpc `VerifyContext` handler — so this is strictly fewer, not more.

## (d) Body toggles — WIRED, not deleted

`ContextCardSpec.exclude_bodies` is stated **negatively** so proto3's `false` default means
"include bodies": a caller that never heard of the field gets its pre-N1.1 pack byte-for-byte.
The builder drops the card's `bodies` section when set, and drops the card with a named omission
(`"bodies (…): code bodies hidden — omitted"`) when that empties it.

Measured, not assumed: `CardTypeSections` maps exactly one card type to the `bodies` section, so
the toggle is a no-op on every other type. `BodyCapableCardTypes` is **derived** from that table
(not a second list), asserted `== ["bodies"]` by `ContextPackLedgerTests`, and the composition view
renders the eye toggle only for those types — so no inert control survives, and the budget panel's
pill (which used to say "All bodies hidden" over a pack containing every body) is hidden entirely
when no card in the pack can carry a body.

## (c) State lifecycle — handle-effect invalidation

Chosen over per-tab keying: the session handle **is** the identity of the graph those `entryIds`
are addressed in, and it is the thing that actually invalidates them; a per-tab key would keep
stale ids alive inside one tab, which is the case the audit measured. The file contained **no
`effect()` at all** (#29); it has one now, and a repo re-analyze clears the cards with a toast
rather than silently degrading them to empty bodies.

Shaping is not session state: budget, intent and format now persist through `PrefsStore`
(`studioBudget`/`studioIntent`/`studioFormat`, clamped on write). Format is a two-way `model()` on
the budget panel with no handler, so it is persisted by a second small effect.

### What `ContextPackLedgerTests` actually asserts (not a smoke test)

1. ledger section keys **≡** the pack's own section keys — set equality, both directions;
2. each ledger row's `FilesChecked` **≡** the distinct file count its own sections cite — so a
   whole-focus file set cannot masquerade as the section's;
3. `AnyStale` agrees with the per-section verdicts (and is `false` on a just-analyzed fixture);
4. hiding bodies drops the card, names the omission, **removes its ledger row**, and shrinks
   `TotalTokens`;
5. `BodyCapableCardTypes == ["bodies"]`, and a non-body card type's pack is byte-identical with the
   flag set — the toggle cannot silently affect cards it does not apply to.
