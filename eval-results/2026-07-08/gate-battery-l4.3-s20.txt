## L4.3 delivered

### Consumers switched to projections
1. **MCP `overview`** (`DevContextTools.cs`) — services + top flows + service links now come from
   `GetGraphFacets` (`ServiceMapProjection` + `FlowListProjection`). Deleted the client-side
   `ServiceStyles.Select`, `entries.OrderByDescending(Score).Take(5)`, and `map.Topology` walks.
2. **MCP `top_flows`** (`DevContextTools.cs`) — deleted the client-side
   `EntryPoints.OrderByDescending(Score).Take(20)`; reads `FlowListProjection.Flows` (server-ranked).
3. **Home hero + Atlas diagram** (`service-map-hero.ts`) — reads `graphFacets.serviceMap.services`;
   renders `DisplayName` verbatim (no `name.split('.').pop()`), gateway/core layout by `Kind`, bus
   rail from projection `transports`. Falls back to topology when facets absent. Atlas diagram reuses
   the same hero, so it inherits the fix.

### Real defect fixed (ratchet, not green-wash)
`ServiceBoundaryInference.IsRunnableService` classified any project with a package whose name merely
*contains* "AspNetCore" as a runnable — so the dogfood library **BuildingBlocks** (refs
`FluentValidation.AspNetCore`) rendered as a service (audit Claim 3 / E3). Tightened to the ASP.NET
shared-framework reference (`Microsoft.AspNetCore.App*`) + Web SDK + Exe (design §2.4). Runnable
Service nodes now tagged `RoleTags.Runnable`; `ServiceMapProjection` surfaces runnable-tagged nodes
only (`IncludeLibraries` opt-in for the full set). Regression tests added.

### Proto (additive)
`FlowCard` gained `node_id`, `route`, `http_method`, `target`, `group_path` so `top_flows` renders
fully from the projection. TS regenerated (`pnpm gen:proto`).
