## Root-cause diagnosis (this session, empirical via a scratch probe)

`approx = edges with Resolution.Syntactic`; verified = everything else. The dominant
approx bucket was **Sends 32/33**. The dispatch pattern is uniform in eShop:
`var command = request.Adapt<XCommand>(); await sender.Send(command);` (and DELETE/GET
endpoints: `sender.Send(new XQuery(...))`).

Tier-B `SemanticLitePopulator` built ONE merged `CSharpCompilation` and tried to bind the
whole initializer `request.Adapt<CheckoutBasketCommand>()`. That bind returned an **error
type** for EVERY invocation in every web/endpoint file, because:
1. **Mapster.dll / Carter.dll are physically absent** from this machine's NuGet caches
   (assets.json present, packages not fully restored) → the `Adapt` extension method can
   never resolve → the whole invocation is an error type.
2. The merged compilation also lacks the **ASP.NET shared framework** (we load only the
   console host TPA, not `Microsoft.AspNetCore.App`) → endpoint files carry hundreds of
   errors.

KEY INSIGHT (probe-proven): binding the **generic type ARGUMENT** `CheckoutBasketCommand`
of `Adapt<CheckoutBasketCommand>` resolves to the real in-scope type
`Basket.API.Basket.CheckoutBasket.CheckoutBasketCommand` **even in the broken merged
compilation** — type-argument resolution is local name resolution and does not depend on
the missing `Adapt` method assembly. Likewise, an inline `new XCommand(..)` object-creation
binds directly (no external package needed). Both are genuine Roslyn semantic binds — not
name guesses — so they earn the Semantic tier honestly.

## L3.3 delivered — assembly-independent semantic binding of dispatch targets

Three focused changes (all upgrade-only, Law R2; zero new edges, zero regex):

1. **`SemanticLitePopulator.BindExpressionType`** (new shared helper): bind whole expression
   first (covers `new X()` and mapping calls when the package IS present); if that yields an
   error type AND the expression is a mapping call (`Adapt<T>`/`Map<T>`/`Create<T>`…) with a
   single explicit generic arg, bind THAT TYPE ARGUMENT directly. Used by
   `TryBindLocalDeclType` (the `var command = …Adapt<T>()` case).

2. **Combined `InvocationOp` upgrade** in `UpgradeBodyFacts`: one case now upgrades receiver
   type + generic args + **argument types**. (Fixes a latent switch-ordering bug where an
   invocation with a receiver never reached the generic-arg branch, so `generic-arg` upgrades
   were always 0.) New `TryBindArgType` binds the inline dispatch arg
   `sender.Send(new XQuery())` / `sender.Send(request.Adapt<XCommand>())` via the same
   `BindExpressionType`. Recorded as `arg-type` in the tier-routing stat.

3. **Lambda-seam overlay generalised** (`GraphBuilder.OverlaySemanticLocals` +
   `AddLambdaSeams`): the re-parsed lambda facts now receive Semantic tiers for ArgFact types
   and generic args (not just `var` locals), matched by (file, expression-text, short-type).
   This carries the whole-file Tier-B binds onto the lambda-anchored edges the trace walks.
