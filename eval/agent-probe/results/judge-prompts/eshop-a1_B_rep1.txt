## What the system is

**eShop is a .NET Aspire–orchestrated, services-based e-commerce reference application** (.NET 10), described in the repo as "A reference .NET application implementing an e-commerce website using a services-based architecture using .NET Aspire" (`README.md:3`). Its 19 projects (`eShop.slnx`) split into runnable services, two client apps, and shared libraries (EventBus, EventBusRabbitMQ, IntegrationEventLogEF, Ordering.Domain, Ordering.Infrastructure, WebAppComponents, eShop.ServiceDefaults).

## The single entry point you actually run

`src/eShop.AppHost` — an Aspire AppHost (`<Project Sdk="Aspire.AppHost.Sdk/13.2.0">`, `OutputType=Exe`, `src/eShop.AppHost/eShop.AppHost.csproj:1-4`). You start it with `dotnet run --project src/eShop.AppHost/eShop.AppHost.csproj` (`README.md:75`) or Ctrl-F5 in Visual Studio (`README.md:71`). Its `Program.cs` builds the whole distributed app graph and calls `builder.Build().Run()` (`src/eShop.AppHost/Program.cs:103`).

## Processes that start when the solution runs

**Backing containers** (`src/eShop.AppHost/Program.cs:7-18`): Redis (`redis`), RabbitMQ (`eventbus`, persistent lifetime), and Postgres using the `ankane/pgvector` image, hosting four databases: `catalogdb`, `identitydb`, `orderingdb`, `webhooksdb`.

**.NET service processes**, each `AddProject<>` in the AppHost:
- `identity-api` — Duende IdentityServer + ASP.NET Identity on `identitydb`, external HTTP endpoints, `/health` check (`src/eShop.AppHost/Program.cs:23-27`; `src/Identity.API/Program.cs:1-30`).
- `basket-api` — gRPC service (`MapGrpcService<BasketService>()`, `src/Basket.API/Program.cs:1-13`), wired to Redis and RabbitMQ (`src/eShop.AppHost/Program.cs:30-34`).
- `catalog-api` — versioned minimal-API Web API over `catalogdb` + RabbitMQ (`src/eShop.AppHost/Program.cs:36-38`; `src/Catalog.API/Program.cs:1-24`).
- `ordering-api` — versioned minimal API with MediatR/DDD layers, `orderingdb`, RabbitMQ, `/health` (`src/eShop.AppHost/Program.cs:40-44`; `src/Ordering.API/Program.cs:1-25`).
- `order-processor` — background worker (Worker SDK, `src/OrderProcessor/OrderProcessor.csproj:1`) hosting `GracePeriodManagerService` over RabbitMQ + `orderingdb` (`src/OrderProcessor/Extensions/Extensions.cs:9-19`); it `WaitFor(orderingApi)` because Ordering.API runs the EF migrations (`src/eShop.AppHost/Program.cs:46-49`).
- `payment-processor` — event-bus subscriber for `OrderStatusChangedToStockConfirmedIntegrationEvent` (`src/PaymentProcessor/Program.cs:1-16`; `src/eShop.AppHost/Program.cs:51-52`).
- `webhooks-api` — versioned Web API over `webhooksdb` + RabbitMQ (`src/eShop.AppHost/Program.cs:54-57`; `src/Webhooks.API/Program.cs:1-26`).
- `webhooksclient` — Blazor server app consuming the webhooks API (`src/eShop.AppHost/Program.cs:65-67`; `src/WebhookClient/Program.cs:1-28`).
- `webapp` — the customer-facing Blazor interactive-server storefront, external endpoints, referencing basket/catalog/ordering/RabbitMQ (`src/eShop.AppHost/Program.cs:69-77`; `src/WebApp/Program.cs:1-30`).
- `mobile-bff` — a YARP reverse proxy resource (not a project) fronting catalog, ordering and identity for mobile clients (`src/eShop.AppHost/Program.cs:60-62`; routes in `src/eShop.AppHost/Extensions.cs:185-215`).

Plus the Aspire dashboard itself, served from the AppHost's launch profile at `https://localhost:19888` (`src/eShop.AppHost/Properties/launchSettings.json`).

## How they are composed

- Composition is entirely declarative in `src/eShop.AppHost/Program.cs`: `WithReference` injects connection strings/service discovery, `WaitFor` orders startup, and `WithEnvironment` threads endpoint URLs (e.g. `Identity__Url`, `CallBackUrl`) between resources; Identity gets back-references to every client, an intentional cyclic reference (`src/eShop.AppHost/Program.cs:96-101`).
- `AddForwardedHeaders()` is a `BeforeStartEvent` hook that sets `ASPNETCORE_FORWARDEDHEADERS_ENABLED=true` on every project resource (`src/eShop.AppHost/Extensions.cs:22-46`).
- HTTP vs HTTPS launch profile is chosen by the `ESHOP_USE_HTTP_ENDPOINTS` env var, for Playwright CI (`src/eShop.AppHost/Program.cs:20`, `:108-116`).
- Every service calls `AddServiceDefaults()`/`AddBasicServiceDefaults()` and `MapDefaultEndpoints()` from the shared `eShop.ServiceDefaults` library (telemetry, health, service discovery) — e.g. `src/Catalog.API/Program.cs:3,17`.
- Inter-service communication: WebApp → Basket over gRPC and → Catalog/Ordering over HTTP; Ordering/Catalog/Basket/OrderProcessor/PaymentProcessor communicate asynchronously via the RabbitMQ event bus.

## Not started by the AppHost

`ClientApp` (.NET MAUI, `src/ClientApp/ClientApp.csproj:1-5`, entry `src/ClientApp/MauiProgram.cs`) and `HybridApp` (MAUI Blazor Hybrid, `src/HybridApp/HybridApp.csproj:1-5`, entry `src/HybridApp/MauiProgram.cs`) are separately-launched mobile/desktop clients — I [REDACTED] `src/eShop.AppHost/` for "ClientApp"/"HybridApp" and found **no** references, so they are not part of the orchestrated run; they talk to the `mobile-bff` proxy. Optional OpenAI/Ollama resources exist but are gated behind `useOpenAI`/`useOllama` flags that are both hardcoded `false` (`src/eShop.AppHost/Program.cs:80-91`), so no AI container starts by default.
