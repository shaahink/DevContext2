## What this is

**eShop ("AdventureWorks") — a .NET Aspire–orchestrated, services-based e-commerce reference application** (`README.md:1`), targeting `net10.0`, with 19 projects in `eShop.slnx`.

## The one entry point you actually run

`src/eShop.AppHost` — the only `OutputType=Exe` host, built with `Aspire.AppHost.Sdk/13.2.0` (`src/eShop.AppHost/eShop.AppHost.csproj:1`). Running it starts the Aspire dashboard on `https://localhost:19888` (`src/eShop.AppHost/Properties/launchSettings.json:6`) and then launches everything else via `builder.Build().Run()` (`src/eShop.AppHost/Program.cs:103`).

### Backing infrastructure (containers)
- **redis** (`src/eShop.AppHost/Program.cs:7`)
- **eventbus** — RabbitMQ, persistent container lifetime (`src/eShop.AppHost/Program.cs:8`)
- **postgres** — image `ankane/pgvector`, hosting databases `catalogdb`, `identitydb`, `orderingdb`, `webhooksdb` (`src/eShop.AppHost/Program.cs:10-18`)

### Application processes started by the AppHost (8 projects + 1 proxy)
| Resource | Project | What composes it |
|---|---|---|
| `identity-api` | Identity.API | ASP.NET MVC + Duende IdentityServer with in-memory clients/resources, ASP.NET Identity on `identitydb`, auto-migration + `UsersSeed` (`src/Identity.API/Program.cs:5-55`); registered with external HTTP endpoints and `/health` (`src/eShop.AppHost/Program.cs:23-26`) |
| `basket-api` | Basket.API | **gRPC-only** service: `app.MapGrpcService<BasketService>()` (`src/Basket.API/Program.cs:12`), Redis-backed `RedisBasketRepository`, subscribes to `OrderStartedIntegrationEvent` (`src/Basket.API/Extensions/Extensions.cs:14-20`); wired to redis + rabbitmq (`src/eShop.AppHost/Program.cs:30-33`) |
| `catalog-api` | Catalog.API | Minimal API `app.MapCatalogApi()` with API versioning and OpenAPI (`src/Catalog.API/Program.cs:13-23`), EF Core `CatalogContext` on `catalogdb` with migration/seed, subscribes to two order-status events (`src/Catalog.API/Extensions/Extensions.cs:15-33`) |
| `ordering-api` | Ordering.API | Versioned minimal API `MapOrdersApiV1().RequireAuthorization()` (`src/Ordering.API/Program.cs:19-22`); MediatR with Logging/Validator/Transaction behaviors, DDD repositories, `OrderingContext` on `orderingdb`, and 5 integration-event subscriptions (`src/Ordering.API/Extensions/Extensions.cs:28-60`) |

| `webhooks-api` | Webhooks.API | Versioned minimal API `MapWebHooksApiV1().RequireAuthorization()` (`src/Webhooks.API/Program.cs:18-21`), `webhooksdb` + 3 event subscriptions (`src/Webhooks.API/Extensions/Extensions.cs:10-23`) |

Cross-cutting: every project calls `AddServiceDefaults()`/`AddBasicServiceDefaults()` and `MapDefaultEndpoints()`, which adds OpenTelemetry, service discovery, and `/health` + `/alive` in Development (`src/eShop.ServiceDefaults/Extensions.cs:108-128`). The AppHost also forces `ASPNETCORE_FORWARDEDHEADERS_ENABLED` on every project resource via a `BeforeStartEvent` hook (`src/eShop.AppHost/Extensions.cs:32-39`).

### Runnable but *not* started by the solution run
- **ClientApp** — .NET MAUI mobile/desktop client (`src/ClientApp/ClientApp.csproj:2`, `src/ClientApp/MauiProgram.cs`); it talks to the backend through `mobile-bff`.
- **HybridApp** — Blazor Hybrid MAUI app (`src/HybridApp/HybridApp.csproj:2`, `src/HybridApp/MauiProgram.cs`).
Neither appears in `src/eShop.AppHost/Program.cs`, so they must be launched separately.

### Optional, currently off
OpenAI/Azure OpenAI and Ollama resources are gated behind `bool useOpenAI = false` and `bool useOllama = false` (`src/eShop.AppHost/Program.cs:80-90`), so no AI container or model resource starts by default — the catalog's semantic-search endpoints exist but run without an embedding provider unless you flip those flags.

Two caveats I'd flag rather than assert: `PaymentProcessor` uses the Web SDK but exposes no business endpoints (only health), so it is effectively a worker despite the SDK; and `mobile-bff` is an Aspire YARP resource (typically a container), which I inferred from `AddYarp` rather than from an in-repo project.
