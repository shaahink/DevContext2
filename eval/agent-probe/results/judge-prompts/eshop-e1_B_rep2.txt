**None.** Basket.API contains no integration event handler that updates prices of items already in a customer's basket when a catalog item's price changes.

- Basket.API has exactly one integration event handler in the whole project: `OrderStartedIntegrationEventHandler` (`src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:6`). Its `Handle` method deletes the user's basket after an order starts — it does no price updating (`src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:10-15`).
- Basket.API's event bus wiring registers only that single subscription: `AddSubscription<OrderStartedIntegrationEvent, OrderStartedIntegrationEventHandler>()` (`src/Basket.API/Extensions/Extensions.cs:19`), and the JSON serializer context lists only `OrderStartedIntegrationEvent` (`src/Basket.API/Extensions/Extensions.cs:24`).
- A repo-wide search for `IIntegrationEventHandler` / `Handle(` under `src/Basket.API` returned only that one handler, and a search for `PriceChanged` matched no file under `src/Basket.API` at all.

For context (not an answer to the question): the price-change event exists elsewhere — it is published by Catalog.API at `src/Catalog.API/Apis/CatalogApi.cs:350` as `ProductPriceChangedIntegrationEvent` (`src/Catalog.API/IntegrationEvents/Events/ProductPriceChangedIntegrationEvent.cs:6`), and its only subscriber in this repo is Webhooks.API's `ProductPriceChangedIntegrationEventHandler` (`src/Webhooks.API/IntegrationEvents/ProductPriceChangedIntegrationEventHandler.cs:3`, registered at `src/Webhooks.API/Extensions/Extensions.cs:21`), which does not touch baskets.

One caveat: this reflects the current source only; if you are comparing against older eShop/eShopOnContainers versions, that codebase did have a `ProductPriceChangedIntegrationEventHandler` in Basket.API, but it is not present here.
