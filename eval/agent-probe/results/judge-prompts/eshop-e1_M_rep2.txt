**None — Basket.API contains no integration event handler that updates prices of items in a customer's basket.**

- Basket.API declares exactly one integration event handler: `OrderStartedIntegrationEventHandler` (`src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:5`), and it deletes the basket rather than repricing anything (`await repository.DeleteBasketAsync(@event.UserId)` at `src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:14`).
- The service's event-bus wiring registers only that one subscription: `AddRabbitMqEventBus("eventbus").AddSubscription<OrderStartedIntegrationEvent, OrderStartedIntegrationEventHandler>()` (`src/Basket.API/Extensions/Extensions.cs:18-19`). There is no second `AddSubscription` call, so no other handler could be invoked in this service.
- An enumeration of every type in the `eShop.Basket.API` namespace returned 25 nodes, none of them a price-changed handler (only `BasketService`, `RedisBasketRepository`, `CustomerBasket`, `BasketItem`, `OrderStartedIntegrationEvent`/handler, and extension/serialization types).
- The price-change event itself, `eShop.Catalog.API.IntegrationEvents.Events.ProductPriceChangedIntegrationEvent`, is only published, at `src/Catalog.API/Apis/CatalogApi.cs:350` (`CatalogApi.UpdateItem`). The only consumer of a `ProductPriceChangedIntegrationEvent` anywhere in the solution is `Webhooks.API.IntegrationEvents.ProductPriceChangedIntegrationEventHandler` (`src/Webhooks.API/IntegrationEvents/ProductPriceChangedIntegrationEventHandler.cs:3`), which sends webhook notifications and is in a different service — not Basket.API.

One caveat worth flagging: `src/Basket.API/Model/BasketItem.cs:8-9` still has `UnitPrice` and `OldUnitPrice` properties, which are vestiges of the older eShopOnContainers design where Basket.API did handle price changes. In this repository nothing writes `OldUnitPrice` from an event handler, so those fields are leftovers rather than evidence of such a handler.
