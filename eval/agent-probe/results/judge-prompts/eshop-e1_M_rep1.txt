**None** — Basket.API contains no integration event handler that updates prices of items already in a customer's basket.

- Basket.API has exactly one integration event handler: `OrderStartedIntegrationEventHandler` (`src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:6`), and it deletes the basket rather than repricing it (`src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:14`).
- The service's event bus wiring registers only that one subscription: `.AddSubscription<OrderStartedIntegrationEvent, OrderStartedIntegrationEventHandler>()` (`src/Basket.API/Extensions/Extensions.cs:18`). There is no `ProductPriceChanged` subscription in Basket.API.
- Enumerating every node in the `Basket.API` service turned up no other `IIntegrationEventHandler` implementation and no `ProductPriceChanged*` type in that project.

For completeness (not the answer, just to show where the price-change event does go): `ProductPriceChangedIntegrationEvent` is raised by Catalog when an item's price is updated (`src/Catalog.API/Apis/CatalogApi.cs:350`), and the only handler for it in the whole solution lives in Webhooks.API — `ProductPriceChangedIntegrationEventHandler` (`src/Webhooks.API/IntegrationEvents/ProductPriceChangedIntegrationEventHandler.cs:3`), which dispatches webhooks and does not touch baskets.

So the "update prices of items already in the basket" behavior (present in older eShopOnContainers versions) does not exist in this codebase's Basket.API.
