## What kind of system this is

**eShop is a .NET Aspire–orchestrated, microservices-based e-commerce reference application** ("AdventureWorks"): a set of independently-hosted ASP.NET Core services that talk over HTTP, gRPC, and a RabbitMQ integration-event bus, plus two .NET MAUI client apps. It is an app, not a library — 19 projects in `eShop.slnx`, described in `README.md:1-3` as "A reference .NET application implementing an e-commerce website using a services-based architecture using .NET Aspire". It targets `net10.0` (e.g. `src/Ordering.API/Ordering.API.csproj:4`).

## The single runnable entry point

**`src/eShop.AppHost` is the one thing you run.** It is an Aspire AppHost (`src/eShop.AppHost/eShop.AppHost.csproj:1` — `Sdk="Aspire.AppHost.Sdk/13.2.0"`, `OutputType=Exe`), started via `dotnet run --project src/eShop.AppHost/eShop.AppHost.csproj` (`README.md:72-75`) or by setting it as the startup project in `eShop.Web.slnf` (`README.md:67-70`). Everything else is composed by `builder.Build().Run()` at `src/eShop.AppHost/Program.cs:103`.

## What does *not* start with the solution

**ClientApp and HybridApp are not launched by the AppHost.** They are .NET MAUI apps (`src/ClientApp/ClientApp.csproj:4`, `src/HybridApp/HybridApp.csproj:4-16`) with `MauiProgram.CreateMauiApp()` entry points, are absent from the AppHost's `AddProject` calls and project references, and are excluded from `eShop.Web.slnf`. They are deployed to devices/emulators separately and reach the backend through the `mobile-bff` proxy — HybridApp hardcodes `http://localhost:11632/` (`src/HybridApp/MauiProgram.cs:9`).

## How composition works

Two mechanisms, layered:

1. **Aspire service discovery / config injection.** `WithReference` injects connection strings and service endpoints (e.g. `webapp` references basket, catalog, ordering, rabbitmq at `Program.cs:72-75`), and `WithEnvironment` wires identity URLs. Note the deliberate cycle: identity-api gets callback URLs for all five clients (`Program.cs:96-101`), while those clients get `IdentityUrl` pointing back at it.
2. **RabbitMQ integration events.** Services are decoupled publisher/subscriber pairs — 13 message consumers across Basket.API, Catalog.API, Ordering.API, PaymentProcessor, WebApp, and Webhooks.API (e.g. `OrderStartedIntegrationEventHandler` in Basket.API, `GracePeriodConfirmedIntegrationEventHandler` in Ordering.API), built on the shared `EventBus`/`EventBusRabbitMQ` libraries.

Shared, non-runnable libraries: `eShop.ServiceDefaults` (telemetry/health/service-discovery, called as `AddServiceDefaults()`/`AddBasicServiceDefaults()` in every host), `EventBus`, `EventBusRabbitMQ`, `IntegrationEventLogEF`, `Ordering.Domain`, `Ordering.Infrastructure`, and `WebAppComponents` (Razor class library shared by WebApp and HybridApp).

One caveat worth flagging: `README.md:12` says "based on .NET 9", but every project actually targets `net10.0` — the README is stale on that point.
