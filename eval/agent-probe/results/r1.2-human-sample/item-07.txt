**None.** Basket.API contains no integration event handler that updates prices of items already in a customer's basket.

Evidence:

- Basket.API subscribes to exactly one integration event, and it is not a price event: `builder.AddRabbitMqEventBus("eventbus").AddSubscription<OrderStartedIntegrationEvent, OrderStartedIntegrationEventHandler>()` — `src/Basket.API/Extensions/Extensions.cs:18-19`. That is the only `AddSubscription` call in the service.
- The single handler that exists in Basket.API is `OrderStartedIntegrationEventHandler` (`src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:6`), and it *deletes* the basket (`await repository.DeleteBasketAsync(@event.UserId);`, `src/Basket.API/IntegrationEvents/EventHandling/OrderStartedIntegrationEventHandler.cs:14`) — it does not re-price anything.
- Enumerating every message-consumer entry point across the solution returns 13 consumers, and the only one belonging to Basket.API is `OrderStartedIntegrationEventHandler`.
- `ProductPriceChangedIntegrationEvent` does exist in Catalog.API (`src/Catalog.API/IntegrationEvents/Events/ProductPriceChangedIntegrationEvent.cs`), but its only usage in the codebase is being *published* from `CatalogApi.UpdateItem` (`src/Catalog.API/Apis/CatalogApi.cs:350`). The only handler named `ProductPriceChangedIntegrationEventHandler` lives in Webhooks.API (`src/Webhooks.API/IntegrationEvents/ProductPriceChangedIntegrationEventHandler.cs`), not Basket.API, and it dispatches webhooks rather than mutating baskets.

Note on likely expectation: in the older *eShopOnContainers* codebase, Basket.API did have a `ProductPriceChangedIntegrationEventHandler` with an `UpdatePriceInBasketItems` method. In this repository (the newer `eShop`) that handler has been removed — baskets in this version store only product ID and quantity/unit price snapshots and are not re-priced on catalog price changes.
