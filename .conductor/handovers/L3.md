## What is thin / shortcut / assumed

| Area | Honesty note |
|------|-------------|
| `GetAwaiter().GetResult()` sync-over-async (lines ~125 in `Populate()`, ~150 in `DiscoveryPipeline`) | Works in console/desktop context but is an anti-pattern. Not fixed — matches pre-existing pattern used throughout the codebase for `IAnalysisCache.GetSyntaxTreeAsync`. |
| `TfmScore` only handles up to net9.0 explicitly | net10.0+ will score lowest (1), potentially choosing a less-compatible TFM. Should enumerate `net\d+` patterns generically. |
| `fileToProject` + `allTrees` built twice | `Populate()` and `DiscoveryPipeline` each build their own mapping and tree list. The cache makes the second pass cheap, but a clean refactoring would return trees/mapping from `Populate()`. |
| No dedicated unit tests for `SemanticLitePopulator` methods | Only integration-tested via the pipeline and truth tests. The private methods (`HasBindDemand`, `MergeSemantic`, bind helpers) lack direct unit coverage. |
| `HasBindDemand` is now maximally permissive | After fix, every body with any InvocationOp passes the gate. This is correct but might cause more `TryBindReceiverType` calls than necessary for bodies that can't benefit (e.g., bodies with only framework-method calls). The cost is caching + a failed node-lookup per body — minimal. |
| DntSite controller sub-measurement (34/94 baseline) | **NOT MEASURED** — the DntSite repo is absent on this machine. Ratchet gate was met on dogfood alone. |

## Risks for L4+

| Risk | Mitigation |
|------|-----------|
| `TfmScore` outdated for future .NET versions | Add pattern-based scoring (`net\d+\.`) before L4 ships |
| NuGet→Framework dedup relies on assembly name match (may miss assemblies with different file names but same identity) | Monitor `DegradeReason` for compilation failures; Roslyn's own error message would surface if duplicate assembly identity escapes |
| `HasBindDemand` now passes almost all bodies through binding — might increase latency marginally | Profile against dogfood (current: ~3.9s, within design budget) |
| Two tree-list builds waste memory | Consider returning `(trees, mapping)` from `SemanticLiteResult` for reuse in `DiscoveryPipeline.UpgradeCallEdges` |
