## What is thin / shortcut / assumed

| Area | Honesty note |
|------|-------------|
| Flow spine `maxSpineDepth=24` | Reasonable for typical HTTP→handler→service→repository depths, but could truncate long pipelines (e.g., event choreography with many hops). Not configurable. |
| Flow spine selects single best out-edge per node (greedy) | Correct for linear dispatch chains (MediatR, direct service calls). Does not capture fan-out (one handler dispatching multiple commands). The trace model is the fan-out surface; the flow spine is intentionally a single "primary" path. |
| Token estimator `(length + 3) / 4` | ~4 chars/token is a common heuristic but off by 30-50% for dense code. The budget slider is a rough guide; exact token counting would need a real tokenizer. |
| BuildSections budget tracking uses `ref int` for remaining budget, shared per-entry | Each entry gets `totalBudget / uniqueFocuses` tokens. With 1 entry, it gets the full budget. This means multi-entry packs split the budget evenly, which may underfund large entries and overfund small ones. |
| BuildMulti concatenates same-type sections from multiple entries with `"\n"` separator | No per-entry sub-headers — two entries' trace skeletons flow together. Ad-equate for the Context Studio use case (copy-once, agent reads all) but could be confusing if entries have very different shapes. |
| ServiceMap `ClassifyService` is tag/title heuristics — no config-based service classification | Gateway/Web API/gRPC detection from title contains and tag matching. Adequate for dogfood target repos but may misclassify non-standard service names. |
| EntryTable stray entries all get `PublicApi` kind | Since EntryPoint nodes don't store their original EntryPointKind (only flows do), stray entries lose their kind. `PublicApi` is the safe generic fallback — it's the "you can trace from this node" kind. |
| AllocatedTokens in ContextPackResponse proto always equals totalBudget, not actual server-side allocation decisions | The RPC receives budget but the server may trim/omit sections — `allocatedTokens` doesn't reflect per-card budget distribution decisions. Currently a pass-through of the requested ceiling. |

## Risks for L5+

| Risk | Mitigation |
|------|-----------|
| Flow spine depth limit (24) could silently truncate deep chains | Add a warning diagnostic when spine depth is exhausted; consider making it configurable via projection options |
| BuildMulti per-entry budget split (even division) may starve large entries | Consider proportional budget allocation based on entry complexity (reach/edges) |
| Section concatenation without per-entry headers may confuse agents reading multi-entry packs | Add `### Entry: {title}` sub-headers when concatenating sections from multiple entries |
| EntryTable stray entries lose kind info (all become PublicApi) | Consider storing EntryPointKind on EntryPoint-kind GraphNodes during assembly, or deriving from node tags |
| No dedicated integration test for GetContextPack RPC end-to-end | Add a server integration test that exercises BuildMulti with multi-entry card specs and verifies section content |
