# L0 — Truth harness · phase handover (audit close-out)

_Audit session #4 · branch `feat/meridian-m0` · base `1e2198a` → audit commit `88783c5`_
_Auditor verdict: **L0 is genuine and useful, but its central gate is not auto-enforced.** Fixes landed for a real green-wash and two harness defects; the biggest risk is process, not code._

Scope audited: the full L0 phase diff (`git diff 1e2198a..HEAD`), i.e. the three
deliverables L0.1 (truth expectation tests + `TruthPendingAttribute` + `bench.ps1 -Truth`),
L0.2 (cold-agent MCP QA harness), L0.3 (UI drive gate). Engine defects the truth
tests encode are **out of scope** by design — they are assigned to L1/L2/L7 via
`[TruthPending]` and must NOT be "fixed" here.

## 1. What is solid and proven

- **Truth tests genuinely execute against real repos (not against DevContext's own
  broken output).** Confirmed by running `dotnet test --filter Category=Truth`:
  `Dogfood_baseline_presence_ok` [607–985 ms], `CleanArchitecture` [1 s], `TodoApi`
  [1–2 s] all do a full analyze + render + assert. These are not stubs.
  Evidence: `eval-results/2026-07-07/truth-gate-l0.1.txt` (pre-audit), re-run this session.
- **The red ratchet is correctly wired.** The 4 known-broken truths are `[TruthPending("Ln")]`
  and report as SKIP with the owning stage in the reason string (L1×2, L2×1, L7×1).
  They cannot silently "pass"; a stage must delete the attribute to claim the fix.
  The assertions themselves are non-trivial and read from source (checkout depth ≥5 +
  named cross-service symbols; no cross-sample edges; runnables-only service set;
  Blazor ≠ Microservices).
- **The trace/overview helpers match the canonical pipeline pattern** used everywhere
  else (`TraceQualityTests.cs:255`, `EngineRunner.cs:86`, `AnalyzeCommand.cs:166`):
  `UnresolvedFocusPoints = FocusPoints = intent.FocusPoints`, then the pipeline
  re-resolves. No divergence — verified against 8 call sites.
- **Cold-agent QA classifier is sound and the 0/12 baseline is trustworthy.** The
  `classify()` axes (signaled-wrong, next-step, false-success, opaque) are pure and
  correctly distinguish the "silent zero-shaped success" trap from real errors.
  Baseline reproduced exactly this session: 0/12 actionable, 5 false-success, 5 opaque.
  Evidence: `eval-results/2026-07-07/mcp-cold-qa.md`.
- **UI drive gate is honest about red.** 1/4 pass (context preset seeds 5 cards),
  3 expected-red with owners (tab strip 18px, New drops tabs, code pane empty). It
  records reds + owner stage and does not green-wash by default.
  Evidence: `eval-results/2026-07-07/ui/ui-gate.md` + 10 screenshots.
- **Full gate battery re-run GREEN this session:** build 0w/0e · tests `Category!=Eval`
  355P/3S + 12P + 64P · `pnpm check` 27/27 · scripted `mcp-qa` 8/8 · truth gate 3P/5S (exit 0).

## 2. Bugs found and fixed (commit `88783c5`)

1. **Green-wash: absent fixture reported as PASS (real defect).** `DntSite_baseline_presence_ok`
   passed in `< 1 ms` with the repo absent (`truth-gate-l0.1.txt:17`), asserting nothing —
   a truth baseline masquerading green. **Fixed:** the 4 baseline tests are now
   `[SkippableFact]` + `Skip.IfNot(...)`, so a missing fixture is an honest SKIP.
   Post-fix: 3 genuine passes + 5 skips (4 ratchet + DntSite-absent). This is
   ratchet-only — no assertion was weakened; a non-run test simply stopped lying.
   Added dependency `Xunit.SkippableFact 1.5.23` (already in local NuGet cache; xUnit 2.9.3
   has no dynamic skip).
2. **Cold-QA rank-quality signal computed then discarded (shallow impl).** The B9
   "resolve Order → aggregate #1" note (audit §4) was built into a local `b9note` and
   thrown away. **Fixed:** hoisted and surfaced in console + `mcp-cold-qa.md`
   (`top="DeleteOrderHandler.Handle" aggregate#1=false results=20`). Baseline unchanged (0/12).
3. **Unhandled-rejection risk on slow analyze (latent crash).** `analyzeRepo` awaited the
   `analyze` promise long after its 45 s per-call timeout could reject it. Reproduced this
   session — analyze took **123 s**; the poll loop recovered the handle but the timed-out
   promise would have surfaced as an `unhandledRejection`. **Fixed:** the rejection is now
   captured at creation (`.then(ok, err => ({error}))`).
4. **Dead code removed:** unused `ExtractInt` (test) and the convoluted no-op `signaledWrong`
   (harness).

## 3. What is shortcut / weak / assumed / NOT fully covered — read this

- **CRITICAL: the truth gate is NOT in the conductor's automated battery.** The truth
  class is `[Trait("Category","Eval")]`, and the conductor runs `dotnet test --filter
  "Category!=Eval"` — so **the truth tests never run in the enforced battery.** They only
  run via `bench.ps1 -Truth` (a manual/evidence path). Consequence: **the conductor cannot
  detect a truth regression, and — more importantly — when L1/L2/L7 flip a `[TruthPending]`
  test green, the conductor will NOT verify it.** The ratchet advances only if a
  human/agent manually runs the truth gate. This is the single largest weakness of L0:
  the harness exists and is real, but its enforcement is manual. See §5 follow-up.
- **Fixture dependence = coverage holes on other machines.** `DogfoodPath()` and
  `DntSitePath()` are hard-coded absolute paths (`C:\Users\shahi\...`); eval-repos resolve
  relative to repo root. On this runner: dogfood + CleanArchitecture + TodoApi + Blazor +
  RazorPages are present and genuinely exercised; **DntSite is absent** (now honestly
  skipped). On a bare CI runner *all* truth tests would skip → the gate would be green
  while proving nothing. Skips are now visible (good), but nothing asserts "≥N truths
  actually ran." A machine with zero fixtures still yields a green truth gate.
- **B9 is a success probe scored inside a failure denominator.** `find "Order"` legitimately
  returns results, yet it counts toward the 0/12 "actionable failures" ratio and can never
  be "actionable." At L5.5 the ≥90% gate math is awkward with B9 in the denominator. Left
  as-is (changing the scoring model is L5.5's job and would alter recorded baseline
  semantics) — flagged for L5.5.
- **UI drive gate can't tell "broken env" from "expected red."** If the server/ng aren't up,
  `page.goto` throws, every assertion fails, all are `expectedRedUntil`, and with `--gate`
  the run is still GREEN (0 unexpected fails). Fine at L0 (gate unarmed) but **L6 must add a
  boot-liveness precondition before arming `--gate`**, or a dead environment will pass.
- **`bench.ps1 -Truth` uses `--no-build` on the test project** but only builds the CLI. On a
  fresh checkout the truth gate fails with a *build* error, not a test result. Harmless
  under the conductor (always builds first); a foot-gun for manual runs.
- **No unit tests for the JS harnesses.** `run-cold.js`/`ui-audit-drive.mjs` have no test
  runner; the pure logic (`classify`, `hasNextStep`) is validated only by end-to-end runs.
  Acceptable for eval tooling, but their correctness is not itself gated.
- **`[TruthPending]` bodies keep their old silent-return fixture guards.** Inert while the
  tests are skipped, but whoever flips them green (L1/L2/L7) should switch those to
  `Skip.IfNot` too, or they'll re-introduce the green-wash for that test.
- **The old `truth-gate-l0.1.txt` evidence shows the pre-fix `4P/4S`** (incl. the DntSite
  fake pass). It was intentionally left as the historical record of the bug; the current
  truth gate is `3P/5S`.

## 4. No engine behaviour was changed
This audit touched only test/harness/evidence files. The four encoded truth defects
(checkout depth-1, fabricated cross-sample edges, class-libs-as-services, Blazor
mislabeled Microservices) are **deferred by design** and remain red for their owner stages.
