## Risks the next phase should watch

1. **conductor-DEBT.md must be resolved before U3 Facet views or next major engine work.** The 8 items are L0-L4 foundations (SymbolTable, BodyFacts, TfmScore, Flow). Working on UI features atop unresolved engine debt is a trap.

2. **eShop TraceQuality failures are the canary for non-CQRS repos.** The L7 call-spine coverage at 69% (post-Loom, post-PlainCallDetector) is good but plateaus. Pushing beyond 70–75% requires tackling the non-CQRS spine (Carter proxy patterns). The eShop 5-failure block is the right place to start.

3. **EvalExpectationTests verticalslice expectations are stale.** Fixing this requires re-benchmarking the VerticalSlice repo and regenerating expectations. This is a data task, not an engine task.

4. **Windows DPI has never been tested.** The desktop app / WPF shell at 125%/150% scaling is unknown territory.

5. **The Server process (PID lock) caused build failures during audit** — `taskkill /F /IM DevContext.Server.exe` needed between test runs. This is a known MSBuild file-locking issue, not a bug in our code, but is an operational friction point.

## Concrete follow-ups

1. **conductor-DEBT.md L0.4** — truth gate auto-enforcement (lowest hanging fruit).
2. **eShop TraceQuality investigation** — 5 failing tests, 1 session.
3. **EvalExpectationTests verticalslice sync** — re-benchmark + regenerate expectations.
4. **Delete `docs/dev/HANDOVER-LOOM.md` when it goes stale** — it will. Conductor should note when the bench baseline drifts >5%.
