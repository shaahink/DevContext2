## Audit defects found and fixed (ratchet-only)

### Fixed
1. **`SymbolTable.GetNamespace` fallback returned FQN instead of namespace.**  
   `GetNamespace("Basket.API.CheckoutBasketCommand")` returned `"Basket.API.CheckoutBasketCommand"` instead of `"Basket.API"`. Fixed to extract last dot-segment.
   → `SymbolTable.cs:118-121` · Test: `GetNamespace_extracts_namespace_for_unregistered_fqn`

2. **`_byProject` dictionary lacked explicit `StringComparer.Ordinal`.**  
   Used default `ValueTuple<string,string>` comparer (implicit ordinal). Added `ByProjectComparer` with explicit `StringComparer.Ordinal` for consistency with `_byShort`.
   → `SymbolTable.cs:26,138-148`

3. **Null `types` parameter threw NRE in constructor.**  
   If someone passed `null` for types, `foreach (var t in types)` threw. Added null guard (`if (types is null) return;`).
   → `SymbolTable.cs:31` · Test: `Null_types_does_not_throw`

4. **Missing test coverage.**
   - `IsAmbiguous`, `IsKnownFqn`, `GetNamespace` — 0 tests → 7 added (including empty/null edge cases)
   - `ServiceBoundaryInference` — 0 tests → 9 added (Exe, WinExe, WebSdk, AspNetCore pkg, WebSdk file, library, test project, filtering, nonexistent file)
   → `SymbolTableTests.cs` (16 tests total) · `ServiceBoundaryInferenceTests.cs` (9 tests)

## What is solid and proven

- **SymbolTable** is structurally correct. Resolution tier chain (Declared → ProjectScoped → GlobalUnique → Ambiguous → Unresolved) has full coverage including same-short-name-different-project (RazorPages scenario), no-context ambiguity, and empty/null inputs.
- **SymboLink/Nodes use Service identity.** All 3 ServiceLink methods (`AddBusServiceLinks`, `AddGrpcServiceLinks`, `AddHttpServiceLinks`) use `NodeId.ForService` + `NodeKind.Service` instead of fake Type nodes. `CodeGraphBuilder.AddNode` correctly merges duplicate Service nodes (preserving Project from `AddServiceNodes`).
- **`_eventPublishers` is safe.** Changed from `static` to instance field — no race condition risk if two `GraphBuilder` instances run concurrently. Initialized fresh per `Build()` call.
- **EntryPoint.Project** is stamped in all 11 entry-point builders (provenance for impact/scope grouping). Property exists on `EntryPoint` record.
- **Guards are tight.** `loom-guards.ps1` correctly enforces L1 rules and tracks L2 advisories. Zero banned patterns.

## What is shortcut / weak / assumed

| Area | Severity | Detail |
|------|----------|--------|
| `RefSite.FromType` | Low | Dead code — never called. Hardcodes `Project = ""`, would produce wrong project-scoped resolution if ever used without `_fileToProject`. **Remove or add `fileToProject` injection before use.** |
| `SymbolTable.Resolve` always uses `SymbolKind.Type` | Low | All `Resolve` return paths create `SymbolId(SymbolKind.Type, ...)`. The resolution logic is sound; the hardcoded Kind is scaffolding until members/endpoints are indexed. |
| `SymbolTable` only indexes `TypeDiscovery` | Medium | `SymbolKind` enum has 8 variants (`Service, Project, Type, Member, Endpoint, Message, Store, ConfigKey`) but only `Type` is populated. L2 should add member/endpoint indexing. |
| `ServiceBoundaryInference.IsWebSdkProject` reads from disk per-call | Low | File I/O in a static method; silent `catch { }` swallows exceptions. Safe for current single-call-per-project pattern, but fragile under repeated calls. |
| No multithreaded GraphBuilder test | Low | `_eventPublishers` is now instance-safe by design, but no test proves concurrent `Build()` calls don't interfere. |
| `AmbiguityReport` is a `class` not a `record` | Low | Testing benefits from structural equality (`record` would give it). Not currently needed. |
| `NodeId.ForService` is case-sensitive | Low | Project names must be consistent across `AddServiceNodes` and ServiceLink methods. Both derive from `ProjectInfo.Name`, so consistent in practice. |

## Risks the next phase (L2) should watch

1. **`SymbolTable` must index members + endpoints.** L2 (BodyFacts + seam detectors) needs `Resolve` to return `SymbolKind.Member` for method/endpoint-level symbols. The table structure supports it; the population side doesn't yet.
2. **`AmbiguityReport` on the dogfood repo should be measured.** After L2 indexing, the ambiguity rate (how many short names are ambiguous) will guide whether namespace-scoped resolution (currently unused `ResolutionTier.Semantic`) is needed.
3. **13 advisory `NodeId.ForType(` in `Graph/`** are tracked by guards as L2 cleanup. Don't let them drift.
4. **`ServiceBoundaryInference` may need caching** if L2 calls it more than once per solution.
5. **`RefSite.FromType`** — either remove dead code or complete it with `fileToProject` injection before L2 uses ref-site factories.
